# DATABASE SCHEMA RULES (POSTGIS REQUIRED)

We are building a production-grade Mining Fleet Management System. Therefore, we MUST use **PostGIS** for spatial data processing.

## Trade-off (To document in README)
- **Why PostGIS?** While standard floats for lat/lon are lighter, PostGIS allows us to perform real-time `ST_Contains` or `ST_Within` queries directly in the database. This is critical for our Geofence feature (knowing when a truck enters a Loading Zone or Crusher) without doing complex math in the Rust backend. The trade-off is a slightly larger Docker image (`postgis/postgis`).

## Required Tables in `init.sql` (5 Tables Architecture)

We use UUIDs for primary keys. Ensure the database has the PostGIS extension enabled: `CREATE EXTENSION IF NOT EXISTS postgis;`

### 1. `fleets` (Master Data)
Stores metadata for both Haul Trucks and Excavators.
- `id` (UUID PK)
- `call_sign` (VARCHAR) -- e.g., 'HT-001', 'EX-042'
- `fleet_type` (VARCHAR) -- 'HAUL_TRUCK', 'EXCAVATOR'
- `make_model` (VARCHAR)
- `status` (VARCHAR) -- 'ACTIVE', 'MAINTENANCE', 'BREAKDOWN'

### 2. `telemetry_logs` (Time-Series Data)
Core table for all vehicle movements.
- `id` (UUID PK)
- `fleet_id` (UUID FK to fleets)
- `timestamp` (TIMESTAMPTZ NOT NULL)
- `geom` (GEOMETRY(Point, 4326) NOT NULL) -- PostGIS Point for Lat/Lon
- `elevation_meters` (FLOAT) -- Crucial for fuel consumption models
- `speed_kmh` (FLOAT)
- `engine_rpm` (INTEGER)
- `fuel_level_percent` (FLOAT)
- `payload_weight_tons` (FLOAT)
- `heading_degrees` (INTEGER) -- 0 to 360, for map icon rotation
- `operational_state` (VARCHAR) -- 'LOADING', 'HAULING', 'DUMPING', 'IDLE'

### 3. `excavator_telemetry` (Excavator Specific Extension)
1-to-1 relationship with `telemetry_logs`. Only populated if `fleet_type` is 'EXCAVATOR'.
- `telemetry_id` (UUID PK, FK to telemetry_logs)
- `boom_angle_degrees` (FLOAT)
- `arm_angle_degrees` (FLOAT)
- `bucket_angle_degrees` (FLOAT)
- `swing_speed_rpm` (FLOAT)

### 4. `geofences` (Spatial Boundaries)
Defines the operational areas in the mine.
- `id` (UUID PK)
- `name` (VARCHAR) -- e.g., 'Loading Zone A', 'Crusher North'
- `zone_type` (VARCHAR) -- 'LOADING_ZONE', 'CRUSHER', 'WORKSHOP'
- `geom` (GEOMETRY(Polygon, 4326) NOT NULL) -- PostGIS Polygon defining the boundary

### 5. `health_alerts` (Anomaly & Rule Engine Logs)
Logs generated by the backend processor when an edge case is detected.
- `id` (UUID PK)
- `fleet_id` (UUID FK to fleets)
- `alert_type` (VARCHAR) -- 'GPS_GLITCH', 'SUSTAINED_OVER_REV', 'OVERSPEED'
- `severity` (VARCHAR) -- 'WARNING', 'CRITICAL'
- `start_timestamp` (TIMESTAMPTZ)
- `end_timestamp` (TIMESTAMPTZ NULL)
- `is_operator_acknowledged` 
- `telemetry_snapshot` (JSONB) -- Snapshots the exact speed/location when the alert triggered for fast debugging

## Indexing Strategy
- Composite index on `telemetry_logs (fleet_id, timestamp DESC)`.
- Spatial index on `telemetry_logs using GIST (geom)`.
- Spatial index on `geofences using GIST (geom)`.
